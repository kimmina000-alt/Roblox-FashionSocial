# 안무 2차 검토 도구 (D-1882)

안무를 넣고 → 포즈 글 비교(`tools/choreo/describe`, D-1863)로 고친 **다음에**, 다른 눈으로 한 번 더 보는 도구입니다.
포즈 글 비교가 "위 / 옆 / 직각" 같은 범주로 비교한다면, 이것은 같은 두 json을 **연속 숫자**로 다시 읽어
범주 안에서 생기는 작은 차이, 박자(ms), 끊는 맛, 바운스를 잡고, 영상 위에 게임 뼈대를 겹쳐 눈으로 확정하게 합니다.

## 흐름

1. 원본 json: `describe/pose_video.py`로 만든 것을 그대로 씀 (곡마다 한 번).
2. 게임 json: 안무를 고친 뒤 **다시 녹화** (`describe/pose_record.lua` → `describe/pose_log.py`). 편집 전 json은 지우지 말고 `--before`로.
3. 검토:
   ```
   python tools/choreo/review/choreo_review.py tws_v.json tws_g.json --video "D:/Roblox/영상/TWS_CallMyName_lAf01WUYtf8.mp4" --out tools/choreo/describe_out/TWS/2차검토 --title "TWS 내 이름을 불러줘" [--before tws_g_편집전.json]
   ```
   몇 초면 끝남. 결과:
   - `검토_리포트.txt` — 한눈에(박자 · hit · 부위별 점수) → 심한 순 → 시간 순. `--before`면 편집 전 → 후 점수, 고쳐진 것, **★새**(편집으로 새로 생긴 것).
   - `review.html` — 뷰어(아래). 원본 영상은 경로로 불러오므로 영상을 옮기면 뷰어의 "영상 파일 직접 열기"로.
   - `issues.json` — 같은 내용(기계용).
4. 뷰어에서 항목을 하나씩 눌러 보고 진짜 / 거짓 경보 / 보류를 고름 → **판정 복사** → 안무 편집에 넘김.

## 보는 것

| 종류 | 무엇 | 기준 |
|---|---|---|
| 모양 | 부위(왼팔 · 오른팔 · 손 · 다리 · 몸통+어깨선 · 고개)의 뼈 방향 각도 오차, 0.02초마다 | 팔 38° · 손 60° · 다리 32° · 몸통 20° · 고개 32°를 0.3초↑ |
| 방향 | 몸이 향한 방향 (카메라 각도 = 곡 전체 중앙값은 뺌) | 50°↑ 0.4초↑ |
| 늦음 / 빠름 | 부위별 2초 창마다 원본과 게임 **속도**를 상관시켜 찾은 시간 차 (+ = 게임이 늦음). 곡 전체 차이는 빼고 판정 | 70ms↑가 1초↑ |
| 늦음 / 빠름 (박) | 박(반박)에 딱 떨어지는 원본 hit 3개↑가 게임에서 70ms↑ 박을 벗어남 | |
| hit 빠짐 | 원본이 빠르게 가다 **딱 멈추는** 순간(hit)인데 게임은 흘러가거나(흐름) 안 움직임(작음) | 같은 부위 1.5초 안 2번↑ |
| 게임만 hit | 원본은 부드러운데 게임만 툭 끊김 · 튐 | |
| 멈춤 / 작음 / 과함 | 1초 창의 움직임 양이 원본의 20% 미만 / 45% 미만 / 2.2배 초과 | |
| 바운스 | 무릎 바운스(골반 높이) · 고개 끄덕임 · 어깨 들썩의 크기(원본의 45% 미만)와 **위상**(원본이 내려갈 때 게임이 올라감) | 1초↑ |

- hit 짝 짓기: 같은 부위의 게임 hit이 ±0.25초 안에 있으면 짝, ms 차이를 냄. 원본 hit은 그 부위 점이 0.2초 앞뒤 모두 읽힌 곳만(가림 · 좌우 뒤바뀜 제외).
- 음악 박: 원본 영상 소리에서 템포 + 위상, 박마다 가까운 온셋으로 맞춤. "박 위 hit 원본 X% / 게임 Y%"가 크게 다르면 박자를 의심.
- 좌우(거울)는 팔 일치도로 스스로 고름(`--mirror on/off`로 강제).
- 원본 쪽 카메라 컷 앞뒤 0.25초와 사람을 못 읽은 곳은 비교하지 않음.

검증: 원본 json을 그대로 0.1초 늦춘 가짜 게임으로 돌리면 모든 부위가 +100ms(±3)로 나옴.

## 뷰어 (review.html)

- 왼쪽: 원본 영상(따라 확대) 위에 원본 뼈대(파랑 = 왼쪽, 빨강 = 오른쪽)와 **게임 뼈대(노랑)**를 겹침. 기준을 넘은 뼈는 분홍 굵게.
  "방향 맞춤"이 켜져 있으면 게임을 원본 몸 방향에 맞춰 겹쳐 팔다리 모양만 비교, 끄면 게임이 실제로 향한 방향.
- 가운데: **정면 · 오른쪽 옆 · 왼쪽 옆 · 위에서** 네 시점에 원본과 게임을 같이 그림(끌어서 돌리기, 두 번 눌러 원래대로).
  정면 영상에서 안 보이는 팔 앞뒤 차이(앞으로 뻗음 vs 옆)는 옆 · 위 시점에서 보임. 아래 막대 = 지금 부위별 오차.
- 아래 타임라인(휠로 확대): 부위별 오차 색, 음악 박(세로 선), ▲ 원본 hit · ▼ 게임 hit와 잇는 선(초록 ±60ms · 주황 ±120ms · 빨강), ✕ 게임에 없음, ◆ 게임에만, 지연 곡선, 움직임 양(×¼ ~ ×4), 무릎 바운스(흰 = 원본, 노랑 = 게임).
- 오른쪽 목록: 심한 순 / 시간 순, 종류 필터(Shift+클릭 = 그것만). 누르면 그 구간을 0.5배속으로 반복.
- 키: Space 재생 · ←/→ 1프레임 · Shift+←/→ 1초 · [ ] 속도 · L 반복 · Z 확대 · N/P 다음/이전 항목.
- 판정은 브라우저에 저장(곡 제목별). 다시 만들어도 같은 번호면 유지되지만 항목 번호가 바뀌면 어긋날 수 있음.

## 한계 · 흔한 거짓 경보

- 원본은 MediaPipe 3D 점이라 **카메라 쪽으로 뻗은 팔**(깊이)이 약함, 빠른 동작은 흐려져서 점이 빠짐(그 순간은 '-').
- 멤버가 가려지거나 카메라 컷 · 줌이 많은 무대 영상은 거짓 경보가 많음: 연습 영상 권장.
- 손(왼손 · 오른손)은 손 모델이 손을 잡은 프레임만 비교 — 작게 찍힌 영상은 판단 보류.
- 게임 녹화는 0.05초 간격이라 hit ms는 약 ±20ms 오차. 더 세밀히 보려면 pose_record의 `Step`을 0.025로.
- 곡 전체가 일정하게 늦거나 빠르면(리포트 맨 위 경고) 춤이 아니라 `pose_video --off` · 녹화 지연을 먼저 확인.
