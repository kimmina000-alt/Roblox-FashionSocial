# 안무 추가 요청서 + 수정 기록 분석 (2026-11-10)

사용자: "안무 추가할 때 말해야 할 거 정리한 거 줘 / 안무 편집하면서 했던 수정 작업들 원인 파악과 해결 방법 분석했던 거랑 아직 분석 못한 부분도 마저 자세하게 분석해 / 발 위치 연결되게 떨림 보정 고개손목 움직임 미세한 것까지 캐치 이런 거 더 있을 거임."

- 1부: 안무를 추가할 때 세션에 붙여 넣을 요청서.
- 2부: 지금까지의 수정(D-840~D-1070, 약 60건)을 원인별로 묶은 표. 이미 자동으로 잡는 것과 아직 사람이 봐야 잡히는 것을 나눴다.
- 3부: 아직 분석 못 했던 유형. 이번에 실제로 잰 것(가림)과 앞으로 만들 검사.

규칙과 도구 사용법 자체는 `CHOREOGRAPHY.md`(§9~§20)에 있다. 이 문서는 그 위의 요약과 빈 곳 찾기다.

## 2부. 지금까지 고친 것: 원인 → 해결 → 지금 상태

"자동" = 게임 코드가 모든 곡에 알아서 함. "검사" = 도구가 찾아 주고 사람이 고침. "눈" = 사용자가 말해야 찾았음.

| freeze가 올라간 팔을 잡음(레몬탱 1:55, D-1192) | freeze는 `from` 순간 자세를 잡음 | `from`을 동작 시작 전으로 | 검사 |
| 같은 키 두 번(네온 calm, D-1192) | ChoreoFixes는 나중 항목이 이김 | 새 항목에 예전 값(calm 등)을 합침 | 검사(grep 키) |

### 2-6. 그 밖 (작업 함정)

- 좌우: 미러 영상 곡은 `mirror = true`. 단 `bend`는 **게임에 보이는 손 이름**으로 적는다(D-1070: 반대 손에 걸렸음).
- 측정: 노래를 멈추면 자세가 바뀐다(멈추지 말고 잰다). 건너뛴 직후 몇 프레임은 값이 튄다. 배경 창은 15fps. freeze는 건너뛴 순간의 자세를 잡으므로 1.5초 앞에서부터 이어 재생해 잰다(D-1068).
- 보정 값(ChoreoFixes)은 처음 읽은 것을 쓴다: Play 중에 바꾸면 안 바뀐다. 소스를 고치고 Play를 다시.
- 플레이리스트 번호는 곡이 추가되면 바뀐다: 번호 대신 제목으로 찾는다(D-1068에서 21번이 다른 곡이 됐음).
- 캡처 동작을 뺄 때(warp · amp · 두 번째 freeze) 그 동작에 딸린 freeze · still 창도 같이 정리하고, 엉덩이 높이 · 방향 · 발을 다시 잰다(D-1190).
- 새 규칙이 생기면 이 문서 + 메모리(choreo-lessons)에 적고 안무 추가 · 무대 카메라 세션에 보낸다(사용자 규칙 2026-11-10).
- 영상 손목 자동 분석: `python -P -E tools/choreo/hand_moves.py <영상> --off <노래-영상 초> --from --to --step 0.05` (MediaPipe 손 모델). 사용자 시간을 받으면 먼저 이걸로 영상의 반짝 · 돌리기 · 꺾기 · 팔 뻗기 시간을 뽑고, 게임 팔 위치와 맞춘다(D-1192).
- 클립 자를 때(무대 카메라 · 센터컷): 손목 · 손이 잘 보이는 장면을 고른다(화면 밖으로 잘림 · 흐림 · 다른 멤버에 가림 없음). 생성기가 손목을 작게 잡으므로 영상에서 보여야 `bend`로 잴 수 있다.
- KeyframeSequence를 Destroy하지 않는다(빈 시퀀스가 옴). MCP 한 번 60초 안(길면 task.spawn + 짧게 읽기).

## 3부. 아직 분석 못 했던 유형

2부의 **눈**은 사용자가 말해야 찾았던 것이다. 아래는 그 유형마다 원인과 미리 찾는 방법이다. 3-1은 이번에 실제로 재 봤고, 나머지는 방법만 정했다(도구는 아직 없음).

### 3-1. 다른 멤버에 가려짐 → 캡처가 깨짐 (이번에 잼)

- 원인: centercut 클립에서 다른 멤버가 센터 앞을 지나가면, 그 순간 추적이 지나가는 사람에게 옮겨 가거나(옷 색이 바뀜) 몸이 가려진다. 그 프레임으로 만든 캡처는 그 구간이 튀거나 멈춘다.
  - 예: Catch Catch 2:06(D-1070, 같은 자리에서 두 번 가려짐), Catch Catch 1:26(D-1018, "무리 속에서 놓침"), 레몬탱 1번 330° 회전(D-1060).
- 찾는 법: `tools/choreo/occlusion_scan.py <centercut 폴더>`. 클립마다 센터의 상자가 다른 사람과 45% 넘게 겹치거나, 몸 관절 신뢰도가 0.45 아래이거나, 옷 색이 그 클립 평균과 달라진(바타차리야 0.5↑) 구간을 클립 초로 출력한다. 영상에서 거의 안 움직이는 0.5초 구간(`still`)도 같이 나온다.

### 3-2. 영상은 움직이는데 캡처가 멈춤

- 원인: 가림(3-1), 업로드가 클립보다 짧음, 생성기가 동작을 놓침.
  - 예: Catch Catch 1:26 7.25초부터 관절 움직임이 1/10(D-1018), Catch Catch 2:06 5.0~5.6초.
- 찾는 법:
  1. occlusion_scan의 0.5초 움직임(몸통 길이로 나눈 관절 속도)과, Studio에서 같은 조각 같은 0.5초의 키프레임 관절 속도를 나란히 놓는다.
  2. 영상이 0.8 넘게 움직이는데 캡처가 평소의 1/3 아래면 표시한다.
- 고치는 법: 3-1과 같다(반복 재생, 다시 업로드). 짧은 멈춤이면 `slowIn` / `slowOut`.

### 3-3. 큰 관절의 강세가 약함 (고개 · 손목 다음 단계)

- 원인: 생성기는 작은 관절만이 아니라 빠른 강세(가슴 튕김, 허리를 깊게 숙이기, 팔 높이, 발차기 높이)도 작게 만든다. 고개 · 손목(§20)은 이제 영상과 비교하지만, 팔꿈치 · 어깨 높이 · 무릎 · 허리는 아직 사용자가 말해야 고쳤다.
  - 예: NEON 1초 허리 24° vs 영상 깊게, NEON 10초 발차기, Catch Catch 1:50 팔, BAD 가슴.
- 찾는 법(head_misses와 같은 틀):
  1. 영상 2D 관절로 0.2초마다 잰다: 손목 높이(몸통 배수), 팔꿈치 각, 허리 숙임(어깨-엉덩이 선 기울기), 무릎 각, 발 높이.
  2. 같은 조각 시간의 캡처를 같은 투영(x = −X, y = −Y)으로 잰다.
  3. 같은 쪽으로 영상의 0.6배 아래인 곳이 2개 이상 이어지면 표시한다.
- 고치는 법: `amp`(관절 배수), `pose add`, `pops`.

### 3-4. 몸통 관통 · 상체 기울기

- 원인: 아바타가 캡처한 사람보다 넓거나(두꺼운 옷), 캡처의 엉덩이 · 허리 기울기가 틀렸다.
- 찾는 법(Play, 사용자 아바타로):
  - 관통: 매 프레임 아래팔 선분과 UpperTorso / LowerTorso 상자 사이 거리. 0.1 아래가 0.2초 넘으면 표시.
  - 상체: 걷기 · 서기 구간(엉덩이가 0.5초에 0.3↑ 이동)에서 UpperTorso가 수직에서 15° 넘게 기울고, 영상 어깨-엉덩이 선은 10° 안이면 표시.
- 고치는 법: 위팔 바깥 `pose add`, `torsoUp`.

### 3-5. 바닥 동작 (앉기 · 눕기 · 무릎 꿇기)

- 원인: 생성기가 바닥 동작을 가장 못 잡는다. 누운 사람을 앉은 자세로, 다리를 엇갈리게 하거나 몸을 떠 있게 만든다.
  - 예: Lemonade 2:12~2:24는 7번 고쳤다(D-976, D-982, D-991, D-1019, D-1058, D-1062, D-1068).
- 찾는 법:
  1. 영상 상자 가로/세로 비율이 1을 넘거나 엉덩이가 발목 높이 근처면 바닥 동작 구간으로 본다.
  2. 그 구간 게임의 엉덩이 높이, 가슴 위 방향(UpVector.Y), 가장 낮은 점(바닥 위 0~0.1이어야 함)을 0.2초마다 표로 낸다.
  3. 바닥 동작은 처음부터 사진 비교(1-3 #14)를 한다.
- 고치는 법:
  - 자세는 `pose set`. 다리 각도는 이번처럼 관절로 위치를 계산해서 찾는다(D-1068 옆으로 앉기).
  - 높이는 `move`로 바닥 위 0.05.
  - 고정은 `freeze` + `still`.
  - 방향은 영상을 따른다(측면이면 측면, D-1068).

### 3-6. 박자 강세

- 원인: 키를 영상의 표시나 눈으로 정해 반 박자씩 틀린다. 애니메이션 시계는 노래보다 0.09초 늦다(D-1058).
- 찾는 법:
  1. 원곡 소리의 박(beats.py)을 구한다.
  2. 캡처 관절 가속도의 정점(가슴 · 손 · 발 튕김)을 구한다.
  3. 정점이 가장 가까운 박에서 0.12초 넘게 떨어진 곳이 이어지면 표시한다.
  4. `pops` · `bend` 키를 넣으면 박 − 0.09초로 둔다.

### 3-7. 손이 몸 · 얼굴에 닿는 자리

- 원인: 영상에서 손이 볼 · 턱 · 허리 · 무릎에 닿아 있어도 캡처는 손이 조금 떨어져 있거나 손목 방향이 다르다.
  - 예: Catch Catch 1:21 볼 톡톡, 끝 자세 손등(D-1070), 레몬탱 2:41 손목(D-1058).
- 찾는 법:
  1. 영상에서 손목 ↔ 코 거리가 머리 크기의 0.6 아래인 구간을 찾는다.
  2. 게임 같은 순간 손 ↔ 머리 거리와 손등 · 손가락 방향을 잰다(D-1070처럼 머리 기준 좌표).
- 고치는 법: 팔은 `pose`, 손목은 `bend`. 손등 · 손바닥이 어느 쪽인지는 사진으로 확인한다.

### 3-8. 같은 안무의 반복

- 원인: 후렴처럼 같은 안무가 여러 번 나오는데, 클립마다 캡처 품질이 다르다(가림, 다른 멤버).
  - 예: Catch Catch 2:06, BAD 2 가슴 튕김(D-1022).
- 찾는 법: 곡 전체 키프레임으로 1~3초 길이의 자세 유사도를 구해(D-1070의 비교), 서로 비슷한 구간 쌍을 낸다. 한쪽만 1-3 #6~#8에서 걸리면 잘 된 쪽을 쓴다.
- 고치는 법: `warp`로 다시 재생하거나 같은 조각을 그 자리에 넣는다.

### 3-9. 업로드 점검 자동화

- 원인: 앞 조각 복사본 업로드(5곡에서 7번), 짧은 업로드, 다른 컷.
- 찾는 법: 1-3 #1을 도구 하나로 묶는다. 길이 차이, 키프레임 해시가 같은 쌍, 클립 수와 id 수를 한 번에 낸다.

1. 영상: `python video_moves.py <centercut 폴더> [클립들] [--beats <영상 파일>]`(centercut .venv). 클립마다 한 줄.
2. Studio Play, Server: `tools/choreo/capture_moves.lua`를 execute_luau로 붙이고, `_G.captureMoves({ clips = { ["13.mp4"] = { id = …, at = …, from = 0 } }, video = [[1의 줄들]], beats = "beats …", videoOffset = 영상 − 노래, mirror = false })`.
   - `mirror`는 **조각을 이 영상에서 캡처했으면 false**(자기 원본과 비교).
3. 나온 구간(곡 초)을 Play로 보고 고친다(§16 표 · 2부 표의 도구).
