## 1. 왜 우리 게임에 맞는가

- 우리 게임의 핵심은 "카탈로그로 꾸민 내 아바타를 보여 주는 것"이다. 인생네컷은 **내 코디를 결과물(사진)로 남기고 친구에게 보여 주는 장치**다. 꾸미기 → 보여 주기 → 기록하기의 루프가 닫힌다.
- 혼자서도 할 수 있고, 친구와 같이 하면 더 재미있다(혼자만/친구와/모두와).
- 프레임·스티커·포즈 팩은 자연스러운 유료 상품이다(참고 게임도 이것이 주 수익원으로 보인다).
- 한국에서 실제로 유행하는 문화라 "리얼함"을 원하는 사용자 성향(MASS 분석)과도 맞는다.

### 2.1 정리: 핵심 루프
`부스 선택(유형·인원) → 대기(친구 합류) → 촬영(8장 × 10초, 포즈·소품) → 4장 고르기 → 프레임 → 저장(인벤토리) → 스티커 꾸미기 → 공유(포토 월 / Roblox 캡처)`

### 2.2 수익 구조
- 게임 재화(코인): 접속 보상·친구 초대로 얻고, 부스 이용(100)·프레임(5~20)·스티커(10~170)·복제에 쓴다.
- 유료: 코인 충전(450/1000/2200 코인 상품), **Photo Pass**(모든 포즈·프레임·스티커), 스페셜 부스.
- 그룹 가입 보상 부스.

### 2.3 기술적으로 어떻게 만들었나 (추정)
Roblox 게임은 화면을 이미지로 저장해 다시 보여 줄 수 없다. 영상의 사진 썸네일은 **ViewportFrame(3D 미니 화면)에 아바타 복제본을 그 순간의 포즈로 다시 세운 것**으로 보인다(작은 캐릭터 실루엣, 회색 배경, 사진이 흐릿하지 않음). 그래서 "PC에서 더 고품질"이라는 안내가 붙는다. 실제 이미지 파일로 남기는 건 Roblox 공식 **캡처(CaptureService)** 기능을 쓴다.

## 3. 우리 버전 범위

### 3.1 MVP (1차)
1. **가게:** City Street 루프 위, 클럽과 공원 사이(회색 박스 08_PhotoBooth). 부스 2개(PINK / WHITE), 포토 월 1면.
2. **부스 입장:** 부스 앞 ProximityPrompt "사진 찍기" → **유형**(1×4 / 2×2) + **인원**(혼자 / 친구와 / 모두와) → [들어가기].
   - 친구와: 친구만 합류 가능. 모두와: 근처 누구나 합류. 최대 4명.
   - 대기 10초 카운트다운(합류 시간), [나가기].
3. **촬영:** 전용 촬영 화면(부스 안 실제 공간 + 고정 카메라).
   - 8장, 장마다 10초 카운트다운 후 자동 촬영. 남은 장수·시간 표시.
   - 왼쪽: 포즈 패널(우리 클럽 춤·포즈·응원 31종 재사용 + 사진 전용 정지 포즈), 오른쪽: 소품 패널(머리띠·안경 등 — 카탈로그 무료 아이템 또는 자체 소품).
   - 캐릭터 이동 가능(구도 맞추기).
4. **고르기:** 8장 중 4장 선택(순서 = 고른 순서), 다시 누르면 해제.
5. **프레임:** 색상 프레임(무료 2종 + 기본 몇 종). 즉시 미리보기.
6. **저장:** 내 사진첩(최대 30장)에 저장 → 핫바/메뉴에서 다시 보기.
7. **공유:** Roblox 공식 캡처 저장(기기 갤러리) + 포토 월에 붙이기(서버 세션 동안).

### 3.2 2차
- 스티커 편집기(이동·회전·크기·삭제), 스티커 팩.
- 유료 프레임·스티커·포즈 팩, "Photo Pass"(또는 VIP 혜택에 포함 여부 결정).
- 친구에게 사진 보내기(같은 서버), 사진 복제.

### 3.3 하지 않는 것
- 공개 갤러리·좋아요·랭킹(PHOTO.md 범위 원칙과 동일).
- 부스 안을 닫힌 작은 방으로 만드는 것(사적 공간 규정, D-043) — 부스는 앞이 열린 형태.
- 게임 재화(코인) 신규 도입은 별도 결정 사항(§8).

## 4. 사진 데이터 설계

사진 1장 = "그 순간을 다시 세울 수 있는 정보"로 저장한다(이미지 파일이 아님).

```
Photo = {
  id, createdAt, layout = "1x4" | "2x2", frame = "<frameKey>",
  shots = { -- 고른 4장
    { people = {
        { userId, outfit = <OutfitSnapshot v1>, pose = { anim = <id>, t = <seconds> },
          cf = <부스 기준 상대 위치/회전>, props = { <assetId>... } } },
      background = "<boothKey>" }
  },
  stickers = { { key, x, y, rot, scale } }  -- 2차
}
```
- 코디는 이미 만든 `OutfitSnapshot`(옷장 저장 형식)을 그대로 쓴다. → 옷장 기능 재사용.
- 보여 줄 때: ViewportFrame에 HumanoidDescription으로 아바타를 만들고, 포즈 애니메이션을 해당 시간에 멈춰 세운다.
- 용량: 4컷 × 최대 4명 × 스냅샷 약 1.2KB ≈ 20KB/장 → 30장 ≈ 600KB. DataStore 키 한도(4MB) 안. 30장 제한을 설정값으로 둔다.
- 다른 사람이 같이 찍힌 사진도 내 사진첩에 내 사본으로 저장된다(상대 코디가 나중에 바뀌어도 사진은 그대로).

## 5. 화면 흐름(우리 버전)

1. 부스 앞 → [사진 찍기] → 유형·인원 선택 창(참고 게임과 같은 3칸 카드 + 인원 3버튼).
2. 대기(10초) → 촬영 화면: 상단 "남은 사진 n · 10초", 좌 포즈, 우 소품, 하단 [나가기].
3. 8장 → "사진을 골라주세요"(8칸 + 미리보기) → [선택 완료].
4. "프레임을 선택하세요"(탭: 색상 / 귀여운 / 특별한) → [다음].
5. 결과: [저장] [캡처 저장] [포토 월에 붙이기].

모바일: 포즈·소품 패널은 접을 수 있게, 촬영 영역이 화면 가운데 50% 이상.

## 6. 서버 권위·보안
- 부스 점유, 참가자, 촬영 시점(서버 시간), 8장 데이터 생성은 서버가 한다. 클라이언트는 고르기·프레임만 보낸다.
- 유료 프레임·포즈는 서버가 소유권을 확인한다.
- 포토 월 게시는 서버 세션 한정, 게시 수 제한(1인 3장), 신고/숨기기.

## 8. 결정이 필요한 항목
1. 부스 이용료: 무료 / 유료(로벅스) / 게임 재화 도입 — 권장: **MVP는 무료**(사진은 퍼지는 홍보물이다), 2차에 유료 프레임·스티커·포즈 팩.
2. Photo Pass를 따로 만들지, VIP 패스 혜택에 포함할지.
3. 사진첩 최대 장수(권장 30).
4. 포토 월을 서버 세션 한정으로 둘지(권장) — 영구 게시는 신고·관리 비용이 크다.

## 9. 제작 시기 (계산)

**의존성:** ① 아바타 코디 스냅샷(옷장, 완료) ② 포즈/춤 재생·동기화(클럽 MVP, 완료) ③ 서버 구매 처리(오늘 완료) ④ 사진 UX 기본(Stage 5) ⑤ 가게 공간(회색 박스, 완료).

**작업량 추정(현재 진행 속도 기준, 1 작업 회차 ≈ 오늘 같은 한 번의 요청 처리):**
| 단계 | 내용 | 회차 |
|---|---|---|
| P1 | 부스 입장·인원·대기, 촬영 화면(1인), 8장 → 4장 → 기본 프레임 → 저장/보기 | 2 |
| P2 | 여러 명 촬영(친구와/모두와), 포토 월, Roblox 캡처 저장 | 1~2 |
| P3 | 스티커 편집기, 유료 프레임·스티커·포즈 팩 | 2 |

**권장 위치: Stage 5(대표 포토 스팟과 사진 UX)를 "인생네컷 P1+P2"로 대체**한다.
- Stage 5의 목표(카메라 구도·포즈·진입/퇴장·여러 명)가 인생네컷과 거의 같다. 따로 만들면 사진 UX를 두 번 만든다.
- 의존성이 모두 끝났다 → 바로 다음 순서로 시작할 수 있다.
- 순서: **클럽 마무리(2인 테스트·모바일) → 인생네컷 P1·P2(Stage 5) → VIP 혜택 정리 → 인생네컷 P3(수익화) → Stage 6 공간들**.
