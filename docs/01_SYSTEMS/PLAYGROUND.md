# Playground — Main Social World Feature Plan

기준일: 2026-10-17  
상태: **신규 월드 구역 제안 / 구현 전**

## 1. 목적

Main Social World에 플레이어가 코디를 구경하거나 사진만 찍는 것 외에 가볍게 놀 수 있는 **놀이터(Playground)** 구역을 추가한다. 놀이터는 게임의 패션·소셜 정체성을 보조하는 장소이며, 카탈로그나 Avatar Editor 같은 핵심 기능을 특정 장소에 가두지 않는다.

현재 요청은 “월드에 놀이터 추가”이므로, 구체적인 놀이기구·미니게임·보상·맵 크기까지 확정된 것으로 간주하지 않는다. 이 문서는 구역 추가를 위한 기본 방향과 결정이 필요한 항목을 분리한다.

## 2. 게임 전체 방향과의 일치

GAME_MASTER.md가 정의한 Main Social World는 자유 탐험, 소셜, 사진, 놀이를 제공한다. 놀이터는 이 목표에 부합한다.

현재 우선 구역:
- Central Plaza
- Club
- Photo Spots
- Park / Playground

후순위 후보: Cafe, Beach, City-Street, Night Area.
보류: Housing District.
미래 확장 후보: Runway Portal.

놀이터는 Park와 연결된 별도 구역 또는 Park 안의 하위 구역으로 두는 것을 우선 검토한다. 아직 맵 배치가 확정되지 않았으므로 이 선택은 **제안**이다. 기존 장소 목록과 충돌하지 않게 GAME_MASTER에는 Playground를 추가하고, 상세한 배치 결정은 월드 blockout 단계에서 확정한다.

## 3. 경험 목표

- 친구와 함께 가볍게 시간을 보낼 수 있다.
- 아바타의 의상과 액세서리가 잘 보이는 공간을 유지한다.
- 플레이어가 조작법을 긴 설명 없이 이해할 수 있다.
- 카메라/캐릭터 이동, 소셜 상호작용, 사진 촬영을 방해하지 않는다.
- 기본 소셜 월드에서 자연스럽게 접근할 수 있고, 별도 Place 이동을 요구하지 않는다.
- 카탈로그와 아바타 편집 UI는 놀이터 안에서도 사용할 수 있다.

## 4. 1차 범위 제안 — Blockout

첫 단계는 세부 아트가 아닌 공간과 이동 동선을 검증하는 blockout이다.

- [ ] Park 또는 Central Plaza와 연결되는 진입 동선
- [ ] 놀이터 구역의 경계와 주요 이동 통로
- [ ] 플레이어가 서로를 보기 쉬운 개방된 중심 공간
- [ ] 여러 플레이어가 동시에 사용해도 겹침이 적은 놀이 지점 배치
- [ ] 앉기/휴식 또는 관람용 공간
- [ ] 스크린샷 촬영에 방해되지 않는 배경과 조명
- [ ] 출입구와 주요 놀이 요소를 쉽게 찾을 수 있는 시각적 랜드마크
- [ ] 모바일에서도 이동·카메라 시야가 막히지 않는 크기와 간격
- [ ] 캐릭터가 끼이거나 튕겨 나가지 않도록 충돌·낙하 영역 확인
- [ ] 기본 Spawn/주요 경로에서 놀이터까지 접근 가능한지 확인

## 5. 놀이 요소 후보 — 아직 미확정

목표는 별도 미니게임을 만드는 것이 아니라 공간에 맞는 짧은 행동으로 아바타를 가지고 노는 재미를 더하는 것이다. 예: 그네에 타면 그네가 움직이고 캐릭터가 앉아서 타는 애니메이션을 한다. 이 예시는 설계 방향이며, 모든 오브젝트를 1차에 구현한다는 뜻은 아니다.

아래는 후보 목록이며, 이번 문서만으로 모두 구현하기로 결정한 것은 아니다.

- 그네 / 시소 / 미끄럼틀 등 기본 놀이터 오브젝트
- 점프·균형 잡기 등 짧은 자유 놀이 상호작용
- 여러 명이 함께 사용할 수 있는 간단한 상호작용
- 벤치 또는 관람석
- 아바타를 보여 주기 좋은 포토 포인트

미니게임, 점수, 순위표, 퀘스트, 일일 보상, 통화 보상은 사용자가 별도로 선택하기 전까지 기본 범위에 포함하지 않는다. 우선은 **자유롭게 돌아다니고 상호작용할 수 있는 공간**을 만든 뒤 실제 플레이 가치가 확인되면 기능을 확장한다.

## 6. 상호작용 기준

놀이 요소를 추가할 때:
- 모바일과 PC에서 접근 가능한 입력 방식을 사용한다.
- 한 플레이어의 상호작용이 다른 플레이어의 캐릭터를 강제로 이동시키거나 방해하지 않도록 한다.
- 상호작용 중에도 아바타 외형을 확인할 수 있어야 한다.
- 상호작용 UI가 열려 있는 동안 카탈로그/Avatar Editor를 여닫을 수 있는지 확인하고, 충돌이 있으면 명확한 우선순위를 정의한다.
- 애니메이션이나 물리 효과를 추가하면 네트워크 소유권, 동기화, 충돌 및 성능을 확인한다.
- 불필요한 강제 리스폰, 순간이동, 카메라 고정을 피한다.

## 7. 성능 및 접근성

- 장식 오브젝트 수와 물리 시뮬레이션을 제한한다.
- 다수 플레이어가 동시에 이용할 때 프레임 저하가 있는지 확인한다.
- 모바일 카메라 시야와 터치 이동 공간을 확보한다.
- 눈에 띄는 이동 경로, 충분한 통로 폭, 상호작용 가능한 오브젝트의 명확한 표시를 사용한다.
- 놀이터 오브젝트가 사진 촬영 시 아바타를 불필요하게 가리지 않도록 한다.

## 8. 구현 순서

1. [ ] 기존 월드 폴더, Spawn, Park/Plaza 배치를 조사한다.
2. [ ] Park 하위 구역인지 별도 인접 구역인지 결정한다.
3. [ ] Blockout 지형과 이동 동선을 만든다.
4. [ ] Roblox Studio에서 PC/모바일 이동과 카메라를 확인한다.
5. [ ] 기본 놀이 오브젝트를 소수만 배치한다.
6. [ ] 상호작용과 다중 플레이어 충돌을 검증한다.
7. [ ] 사진 촬영, 카탈로그, 아바타 편집 흐름을 회귀 테스트한다.
8. [ ] blockout 검증 후 아트·조명·세부 오브젝트를 추가한다.

## 9. 완료 기준

- [ ] Main Social World에서 별도 Place 이동 없이 놀이터에 접근할 수 있다.
- [ ] PC/모바일에서 이동과 카메라 조작이 가능하다.
- [ ] 주요 통로와 상호작용 오브젝트에서 캐릭터가 끼이거나 비정상적으로 튀지 않는다.
- [ ] 여러 플레이어가 동시에 공간을 이용할 수 있다.
- [ ] 놀이터에서 아바타를 확인하고 사진을 찍을 수 있다.
- [ ] 카탈로그와 아바타 편집 기능이 월드 구역 때문에 제한되지 않는다.
- [ ] Studio에서 직접 테스트한 항목과 미검증 항목이 구분되어 있다.

## 10. 아직 결정할 질문

- 놀이터는 Park 안에 둘까, Park와 Plaza 사이의 독립 구역으로 둘까?
- 단순한 장식형 놀이터로 시작할까, 플레이어가 직접 조작하는 그네/시소/미끄럼틀을 1차에 포함할까?
- 상호작용 애니메이션을 먼저 구현할까, 기본 이동·충돌 blockout을 먼저 검증할까?

위 질문은 공간 배치와 1차 범위를 결정하기 위한 항목이다. 별도 지시가 없다면 **Park와 연결된 blockout + 소수의 기본 상호작용**을 기본 제안으로 삼고, 보상/미니게임 시스템은 추가하지 않는다.


## Priority Alignment — 2026-10-18

Playground is a small interaction extension of Main Social, after the Catalog/SavedOutfits, Club and Photo Spots core work. Start with blockout and a few interactions only. Do not introduce a separate Place, reward loop, quests, leaderboards or broad minigame systems without a separate decision. Housing remains deferred and Runway remains a future candidate.
