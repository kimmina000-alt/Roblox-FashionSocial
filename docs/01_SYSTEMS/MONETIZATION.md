# Monetization & VIP Design

상태: **기획 기준안 — 구매 기능 구현 또는 Studio 검증 완료를 의미하지 않음**  
기준일: 2026-10-19

## 1. 목표와 원칙

Roblox-FashionSocial의 수익화는 아바타 표현과 사진 촬영 선택지를 확장하는 것을 목표로 한다. 기본 소셜 경험이나 카탈로그 핵심 기능을 구매 장벽으로 만들지 않는다.

- 무료 이용자도 카탈로그를 검색하고, 지원 아이템을 미리 착용해 보고, 기본 포즈와 핵심 소셜 기능을 이용할 수 있다.
- 유료 혜택은 외형과 표현 선택지를 확장하며 경쟁 우위나 필수 진행을 판매하지 않는다.
- 구매 전 상품 구성과 가격을 명확하게 보여 준다. 허위 한정 판매, 부정확한 할인, 압박성 문구를 사용하지 않는다.
- 카탈로그 아이템 검색/미리보기와 실제 Robux 구매는 별개의 흐름이다. Try-on은 아이템 소유권을 의미하지 않는다.
- 기획상 결정, 코드에 존재하는 동작, 사용자가 확인한 동작, Studio 검증 결과를 구분한다.

## 2. 확정된 상품 결정

| 상품/기능 | 결정 | 범위 |
|---|---|---|
| VIP | 일회성 VIP Pass | 소유 시 VIP 혜택 사용 가능 |
| VIP 외곽선 | 추가 색상·스타일 | 기본 아바타/소셜 경험은 VIP 없이도 이용 가능 |
| VIP 배지 | 다른 이용자에게 표시 | 소셜 공간에서 VIP 상태를 시각적으로 식별 |
| 추가 사진 포즈 | 포즈 묶음별 직접 구매 | VIP와 별개의 상품 권한 |
| 카탈로그 검색 | 무료 | 검색 및 카테고리 탐색 |
| 아이템 미리보기/임시 착용 | 무료 | 지원되는 아이템 유형 범위 내 |
| 기본 사진 포즈 | 무료 | 사진 촬영 기능의 기본 경험 |
| 핵심 소셜 기능 | 무료 | 이동, 다른 플레이어와의 상호작용 등 기본 경험 |

위 결정은 상품의 개념과 무료/유료 경계를 확정한다. 가격, 콘텐츠 수량, 최종 시각 디자인과 실제 Roblox 상품 ID는 아직 확정하지 않는다.

## 3. 권한 모델 원칙

VIP와 개별 포즈 묶음의 소유권은 서로 독립적이어야 한다. VIP 보유만으로 별도 구매 포즈 묶음을 자동 소유하지 않으며, 포즈 묶음만 구매한 이용자도 해당 묶음의 포즈를 사용할 수 있어야 한다.

개념적 권한:

- `HasVIP`: VIP Pass 소유 여부
- `OwnedPosePacks`: 소유한 포즈 묶음 집합
- `EquippedOutlineStyle`: 현재 선택한 외곽선 스타일
- `SelectedPose`: 현재 선택한 포즈

이는 개념 모델이며 실제 변수명이나 데이터 구조를 확정하는 것은 아니다. 구현 전 현재 서버/클라이언트 구조와 저장 정책을 검토한다.

### 서버 권위와 구매 검증

- 유료 혜택의 권한 판단은 클라이언트가 보내는 플래그만 신뢰하지 않고 서버에서 검증한다.
- UI의 구매 완료 메시지만으로 상품 권한을 부여하지 않는다. Roblox 구매 결과와 상품 유형에 맞는 검증 절차를 사용한다.
- 구매 취소, 실패, 검증 오류, 네트워크 오류가 발생해도 상품을 잘못 지급하거나 무료 기능을 막지 않는다.
- 소유 여부를 확인할 수 없는 경우에는 안전하게 제한된 상태를 표시하고 다시 확인할 수 있게 한다.
- 재접속, respawn, 서버 이동 이후에도 권한이 일관되게 반영되는지 테스트한다.
- 실제 영구 데이터가 필요한 경우 schema 버전과 실패 복구를 설계한다. 영구 소유권을 클라이언트 저장값만으로 판단하지 않는다.

## 4. VIP Pass 혜택

### 4.1 추가 외곽선 색상과 스타일

VIP는 기본 제공 범위를 넘어서는 추가 외곽선 색상과 스타일을 사용할 수 있다.

요구사항:
- 적용 전 미리보기와 선택/해제 동작을 제공한다.
- 선택한 스타일이 다른 플레이어에게도 보이는지 검증한다.
- 스타일 미적용, 캐릭터 respawn, 캐릭터 변경 및 UI 재오픈 상황에서 상태가 꼬이지 않도록 한다.
- VIP 권한이 없는 이용자는 무료 범위의 외형 기능을 계속 사용할 수 있다.
- 외곽선 기능은 구매 UI와 분리해 테스트할 수 있도록 한다.

색상 수, 스타일 수, 렌더링 방식은 구현 단계에서 아트 방향과 성능을 확인한 뒤 결정한다.

### 4.2 VIP 배지

VIP 보유 상태를 다른 이용자에게도 표시한다. 배지는 소셜 식별용 장식이며 게임 플레이 능력이나 우선권을 부여하지 않는다.

요구사항:
- 서버에서 확인된 VIP 상태를 기반으로 표시한다.
- 다른 플레이어의 화면에서도 표시 상태가 일관되어야 한다.
- 캐릭터 respawn과 플레이어 입장/퇴장 상황을 검증한다.
- 이름표와 캐릭터를 가리거나 모바일 화면을 과도하게 복잡하게 만들지 않는다.

배지의 최종 모양, 크기, 색상과 정확한 위치는 구현 직전에 결정한다.

## 5. 사진 포즈 묶음

추가 사진 포즈는 VIP와 분리된 직접 구매 상품으로 제공한다. 구매한 묶음의 포즈는 소유권이 확인된 이용자가 반복해서 사용할 수 있는 영구 소유형 콘텐츠를 목표로 한다.

요구사항:
- 기본 포즈는 무료로 유지한다.
- 구매 전에 묶음에 포함된 포즈와 가격을 확인할 수 있다.
- 소유한 묶음은 다시 구매하도록 유도하지 않고 보유 상태를 표시한다.
- 포즈를 선택하고 적용한 뒤 일반 이동/카메라 상태로 돌아올 수 있다.
- 미소유 포즈는 미리보기 허용 범위를 명확히 하고, 실제 사용 권한은 서버에서 검증한다.
- VIP 소유 여부와 포즈 묶음 소유 여부를 별도로 검사한다.

### 상품 유형 결정 시점

포즈 묶음은 구매 후 영구적으로 보유하는 콘텐츠로 설계한다. 각 묶음의 실제 Roblox 상품 유형은 구현 직전에 현재 Creator Hub 정책과 API, 소유권 조회 및 지급 흐름을 확인한 뒤 선택한다. 모든 묶음을 무조건 같은 상품 유형으로 구현한다고 미리 가정하지 않는다.

첫 묶음의 포즈 종류와 수량, 묶음 수, 가격은 아직 미정이다.

## 6. 상점 및 구매 UX

- 상품 카드에는 상품명, 포함 혜택, 가격, 보유/미보유 상태를 명확히 표시한다.
- 가능하면 구매 전에 외곽선이나 포즈의 시각적 예시를 보여 준다.
- 구매 프롬프트를 취소하거나 닫아도 게임 진행을 막지 않는다.
- 구매 완료 여부를 확인한 뒤 혜택을 활성화한다.
- 이미 보유한 상품은 구매 대신 보유 상태를 보여 준다.
- 허위 재고, 가짜 카운트다운, 압박성 구매 문구를 사용하지 않는다.
- 상점은 무료 카탈로그 검색, 미리보기, 기본 포즈와 핵심 소셜 경험을 가로막지 않는다.

## 7. 구현 시점과 의존성

VIP 구매 기능은 카탈로그 핵심 기능보다 우선하지 않는다. 실제로 판매할 혜택이 구현되기 전에 구매 시스템을 먼저 완성하면 미완성 상품을 테스트하기 어렵고, 기존 기능을 다시 연결해야 할 수 있다.

권장 순서:

1. **Stage 1 — Catalog 핵심 흐름:** 검색, 지원 아이템 미리보기/착용/해제, 서버 확인 상태와 다른 플레이어에게 보이는 외형을 안정화한다.
2. **Stage 2 — SavedOutfits/DataStore:** 저장 스키마와 서버 권위형 데이터 원칙을 구현한다. VIP 소유권과 코디 데이터는 별도 개념으로 유지한다.
3. **Stage 3 — Main Social 블록아웃 및 아바타 표시 기반:** 이름표/캐릭터 표시와 다중 사용자 가시성의 기반을 확보한다. Stage 1과 병행할 수 있다.
4. **Stage 4 — Club MVP:** 기존 개발 순서에 따라 기본 춤 기능을 완성한다.
5. **Stage 5 — Photo Spots 및 사진 UX:** 기본 카메라·포즈·진입/퇴장 흐름을 먼저 구현하고 검증한다.
6. **기반 기능이 준비된 뒤 — VIP/수익화 구현:** VIP Pass 검증, 배지, 추가 외곽선, 포즈 묶음 권한, 구매 흐름을 연결한다. 월드 제작의 모든 단계를 끝낼 때까지 무조건 기다릴 필요는 없으며, 해당 기능의 의존성이 준비되면 별도 수직 기능으로 진행할 수 있다.
7. **통합 QA:** 구매/취소/실패/재접속, 권한 분리, 다른 플레이어 표시, PC/모바일을 검증한다.

구현 순서의 기준 문서는 `docs/00_PROJECT/DEVELOPMENT_ORDER.md`다. 이 문서는 수익화의 상품 및 권한 규칙을 정의하고, 전체 개발 순서 문서는 의존성과 작업 시점을 관리한다.

## 9. 완료 및 QA 기준

VIP/수익화 기능은 코드가 존재한다는 이유만으로 완료 처리하지 않는다.

- [ ] VIP를 보유하지 않은 이용자는 무료 기능을 정상적으로 사용한다.
- [ ] VIP 보유자는 서버에서 확인된 뒤 VIP 배지와 추가 외곽선을 사용할 수 있다.
- [ ] 배지가 다른 플레이어에게도 표시된다.
- [ ] VIP 보유만으로 미구매 포즈 묶음이 잠금 해제되지 않는다.
- [ ] 구매한 포즈 묶음은 VIP가 없어도 사용할 수 있다.
- [ ] 구매 취소/실패/검증 오류가 잘못된 지급이나 무료 기능 차단으로 이어지지 않는다.
- [ ] 재접속 및 respawn 후 권한이 일관되게 반영된다.
- [ ] PC와 모바일에서 상점, 외곽선 설정, 포즈 선택을 사용할 수 있다.
- [ ] 기존 카탈로그, 코디 저장, 소셜 이동 흐름에 회귀 문제가 없다.
- [ ] 실제 테스트하지 않은 항목은 Studio-verified로 표시하지 않는다.
