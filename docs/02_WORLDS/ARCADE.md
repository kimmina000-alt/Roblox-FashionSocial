# 오락실 (기획, 2026-11-19)

상태: **기획만 있음, 코드 없음.** 우선순위 P3 (진행표 `docs/00_PROJECT/PROGRESS_TRACKER.md`).

## 1. 사용자 방향 (2026-11-19)

> "오락실 너무 크면 별도 서버로 만들어서 연결해서 점수 기록 세울 수 있게 해야겠다."

- 오락실이 크면 메인 맵(오후)에 넣지 않고 **별도 플레이스**로 만들어 메인 맵과 연결한다.
- 게임마다 **점수 기록(순위표)** 을 세울 수 있게 한다.

## 2. 구조안

**같은 경험(10773076711) 안에 두 번째 플레이스를 둔다.** 다른 경험이 아니라 같은 경험의 서브 플레이스로 둔다.

| 항목 | 방법 | 이유 |
|---|---|---|
| 들어가기 | 메인 맵 오락실 입구 → TeleportService로 오락실 플레이스 이동 | 메인 맵 부품 · 메모리 예산(PERFORMANCE.md, 11-15 메모리 부족 종료)에 영향 없음 |
| 나오기 | 오락실 출구 → 메인 맵으로 이동, 오락실 입구 앞에 내림 | 길 잃지 않게 |
| 친구와 같이 | 같이 온 사람들(파티)을 같은 오락실 서버로 보냄 | "지인이 지인을 데려옴"(PLAYER_FEEDBACK) |
| 코인 · 옷 · 가방 | 같은 경험이면 DataStore를 같이 씀 → 지갑 · 옷 그대로 | 오락실에서 쓴 코인이 메인에도 반영 |
| 점수 기록 | 게임마다 OrderedDataStore (전체 순위), 오늘 · 이번 주 순위는 키에 날짜를 넣어서 | 서버가 달라도 같은 순위표 |
| 메인 맵에 보여 주기 | 오락실 입구 옆 순위판(놀이공원 계단 순위판 D-1821과 같은 방식) | 메인 맵에서도 기록이 보여야 도전하고 싶어짐 |
| 점수 확인 | 점수는 서버가 계산 · 저장 (클라이언트가 보낸 숫자를 그대로 믿지 않음) | 조작 방지 |

## 3. 정할 것 (사용자)

1. **크기 기준:** 게임 몇 개부터 별도 플레이스로 뺄지. 작으면(게임 2~3개) 메인 맵 안 건물로 두고 순위표만 같은 방식으로 둘 수도 있다.
2. **게임 목록:** 인형 뽑기, 리듬(클럽 곡 재사용), 펀치 / 농구, 레이싱, 사진 스티커와 연결 등.
3. **메인 맵 입구 위치:** 거리 상가, 놀이공원 옆, 지하.
4. **상(보상):** 순위 1~3위 칭호(FOUNDING MEMBER 같은 이름표 칭호), 코인, 없음.
5. **돈:** 한 판 코인 / 무료. 판매 안내가 많다는 의견(11-15)이 있으니 Robux 상품은 조심.

## 4. 주의

- 이동 중 로딩 화면이 생긴다. 메인 서버의 상태(클럽 테이블, DJ 시간, 들고 있던 풍선 · 튜브)는 따라가지 않는다. DJ 이용권(D-1810)처럼 나갈 때 돌려주는 규칙이 필요하다.
- 서브 플레이스는 따로 게시해야 하고, Studio 테스트도 따로 해야 한다(텔레포트는 Studio에서 안 됨, 라이브에서 확인).
- 번역 · 첫 방문 투어 · 메뉴(☰) 같은 공통 코드는 두 플레이스가 같이 써야 한다. Rojo 프로젝트를 하나 더 만들어 `src/` 공통 부분을 같이 매핑한다.
