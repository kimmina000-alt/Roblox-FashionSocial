기준일: 2026-10-18  
상태: **설계 작업 지침 / 맵 배치와 에셋 삽입이 완료되었다는 뜻이 아님**  
적용 프로젝트: Main Social World  
관련 문서: `docs/02_WORLDS/WORLD_CONCEPTS_AND_INTERACTIONS.md`, `docs/00_PROJECT/DEVELOPMENT_ORDER.md`, `docs/04_ART/WORLD_DESIGN_EXPLORATION.md`

## 1. 목적

이 문서는 Main Social의 공간을 감으로 나열하지 않고, 공간 프로그램·인접 관계·플레이어 동선·시야·플레이 경험을 바탕으로 배치한 뒤 Roblox Studio에서 빠르게 검증하기 위한 작업 기준이다.

핵심 원칙:
- 모든 건물을 직접 모델링하지 않는다.
- 모든 공간의 세부 아트를 한꺼번에 완성하지 않는다.
- 먼저 공간의 관계와 이동 구조를 설계하고, 간단한 블록아웃으로 검증한다.
- 블록아웃은 완성 건물의 회색 복제품을 만드는 일이 아니다. 크기, 위치, 통로, 진입 방향, 랜드마크, 카메라 시야를 검증하는 저비용 모델이다.
- 단순한 소품과 반복 가능한 건축은 검증된 Creator Store 에셋/모듈을 우선 검토한다. 게임 정체성을 만드는 핵심 랜드마크만 맞춤 제작을 검토한다.
- 이 문서의 공간 배치는 제안이다. 사용자 승인과 Studio 테스트 전에는 확정된 맵 설계로 취급하지 않는다.

## 2. 설계자가 먼저 만드는 도면 순서

다이어그램은 하나의 그림에 모든 정보를 넣지 않고, 각 단계에서 질문 하나를 분리해 검토한다.

1. **공간 프로그램(Program):** 각 구역의 목적, 주요 행동, 예상 체류, 필수 랜드마크를 정리한다.
2. **인접 관계(Adjacency):** 어떤 공간끼리 가까워야 하는지, 직접 연결해야 하는지, 분리해야 하는지 정한다.
3. **버블 다이어그램(Bubble Diagram):** 공간의 상대적 크기와 관계를 원/영역으로 배치한다. 이 단계에서 정확한 건물 형태를 결정하지 않는다.
4. **존닝(Zoning):** 소셜/활동/휴식/탐험/사진/서비스와 같은 기능을 구역으로 묶는다.
5. **동선 다이어그램(Circulation):** 스폰 지점, 주요 경로, 선택적 우회, 막다른 길, 공간 간 이동, 재방문 루프를 표시한다.
6. **매스 다이어그램(Massing):** 단순한 입체 덩어리로 건물 높이, 랜드마크의 시각적 위계, 개방/폐쇄, 바다·옥상·돔 등 주요 실루엣을 검토한다.
7. **회색 블록아웃(Graybox):** Roblox Studio에서 바닥·벽·박스·경사·임시 표지로 이동과 시야를 실제 카메라에서 테스트한다.
8. **에셋 교체 및 아트 패스:** 치수가 맞는 에셋을 넣고 조명·색·재질·장식을 조정한다.
9. **플레이 테스트 및 수정:** 실제 이동 속도, 점프, 모바일 화면, 충돌, 동시 플레이어, 성능을 보고 다이어그램과 블록아웃으로 되돌아가 수정한다.

이 순서는 선형 공정이 아니라 반복 과정이다. 테스트에서 동선 문제가 나오면 건물 장식을 추가하기 전에 배치부터 수정한다.

## 3. 설계할 때 확인할 질문

각 공간에 대해 다음을 기록한다.

- **목적:** 플레이어가 이곳에 왜 오고, 어떤 행동을 하는가?
- **진입:** 어디에서 들어오며 입구가 멀리서 읽히는가?
- **인접:** 어떤 공간과 가까워야 하고, 무엇과 소리/시각적으로 분리해야 하는가?
- **동선:** 통과 공간인가, 머무는 목적지인가, 선택적 탐험 공간인가?
- **위계:** 첫 진입 시 무엇이 가장 먼저 보여야 하는가?
- **시야:** 다음 목적지나 랜드마크가 보이는가? 사진 배경과 아바타 실루엣이 잘 읽히는가?
- **체류와 밀도:** 친구들이 모여도 통로를 막지 않는가? 활동 공간과 관람 공간이 충돌하지 않는가?
- **접근성:** PC와 모바일에서 길을 찾고 상호작용하기 쉬운가?
- **회복/복귀:** 길을 잃거나 탐험을 마쳤을 때 중심 공간으로 돌아오기 쉬운가?
- **제작비:** 이곳은 에셋 조합으로 충분한가, 아니면 고유 랜드마크가 필요한가?

## 5. 초기 배치 가설 — 검증 전 제안

정확한 거리나 방향을 확정하기 전, 관계만 가정한다.

- Main Social은 길 찾기의 기준점이자 구역 선택의 허브가 된다.
- Club은 중심 허브에서 찾기 쉽되, 활동 구역의 시각적/공간적 존재감이 분명하도록 둔다.
- Beach와 Dream Aquarium는 하나의 해안 경험으로 연결한다. 돔은 해변에서 발견할 수 있는 랜드마크로 둔다.
- Glasshouse Cafe는 비교적 조용한 휴식 목적지로 두고, Club의 주 동선과 소음/시각적 경쟁이 적도록 검토한다.
- Neon Rooftop City는 카페와 별도 공간으로 유지할지, 같은 도시 권역에 둘지 매스 다이어그램 비교 후 결정한다.
- Fantasy Playground는 움직이는 상호작용과 사진을 지원할 충분한 개방 공간을 확보한다.
- City Street는 여러 구역을 연결하는 경로로 쓸 수 있지만, 반드시 모든 장소가 한 줄로 연결되어야 하는 것은 아니다.
- Photo Spots는 주요 구역에 분산한다. 특정 포토 스팟이 통로를 막지 않도록 한다.
- Fashion Week Backstage는 현재 핵심 루프와 분리된 확장 후보로 남긴다.
- 플레이어가 길을 잃지 않도록 랜드마크, 표지판, 색상/조명 차이를 사용한다. 포털은 연결을 단순화하는 선택지이지, 공간 간 관계를 검토하지 않고 배치를 생략하는 수단은 아니다.

## 6. 블록아웃과 에셋 사용 원칙

### 블록아웃에서 반드시 확인할 것
- 스폰 지점에서 주요 목적지의 방향을 이해할 수 있는가
- 주요 통로에서 두세 명 이상이 마주쳐도 지나갈 수 있는가
- 입구/출구와 포털이 배경 속에 묻히지 않는가
- 플레이어 높이 기준으로 건물, 돔, 무대, 나무 등이 적절한 크기인가
- 카메라가 벽/천장에 끼거나 사진 구도를 방해하지 않는가
- 주요 활동 구역에서 플레이어 아바타가 잘 보이는가
- 모바일에서도 랜드마크와 상호작용 대상이 읽히는가

### 처음부터 에셋을 사용해도 되는 것
- 벤치, 나무, 가로등, 테이블, 의자, 화분, 장식 소품
- 반복 가능한 창문, 기둥, 난간, 벽 패널 등 모듈형 건축 부품
- 검증된 간판/조명/장식 모델

### 우선 블록아웃으로 크기와 관계를 검증할 것
- 전체 지도와 구역 간 거리
- Club 무대와 댄스 플로어의 비율
- Aquarium 돔과 해안/수중 출입 경로
- Rooftop의 높이와 접근 경로
- Playground의 놀이기구 간 간격
- 주요 포털/게이트의 위치

### 맞춤 제작을 고려할 만한 요소
게임의 공간 정체성을 만드는 Club 무대, Dream Aquarium의 돔, 특색 있는 포토 랜드마크 등. 먼저 Creator Store와 모듈 조합으로 구현 가능한지 확인한다.

## 7. Creator Store 에셋 후보

다음은 조사 후보이며 **프로젝트에 삽입·검증·채택 완료된 에셋이 아니다.** Creator Store의 가격, 소유자, 구성, 권한은 실제 사용할 때 다시 확인한다.

   https://create.roblox.com/store/asset/110451947031288/StudsPackBeach

### 에셋 보안·성능 체크리스트
- [ ] Creator Store 페이지에서 제작자, 사용 조건, 업데이트 상태를 확인한다.
- [ ] 모델 내부의 Script/LocalScript/ModuleScript를 확인하고 불필요하거나 이해할 수 없는 코드는 실행하지 않는다.
- [ ] 모델이 요구하는 외부 에셋/패키지 의존성을 확인한다.
- [ ] 중복된 파트와 과도한 MeshPart/텍스처/파티클을 줄인다.
- [ ] 크기, Pivot, 충돌, Anchored 상태를 검사한다.
- [ ] 별도 테스트 장소에서 실행 후 본 맵에 넣는다.
- [ ] 모바일 성능과 실제 플레이어 동선을 확인한다.

## 8. 참고 자료와 근거 구분

### 공식 Roblox 자료
- Studio MCP: https://create.roblox.com/docs/studio/mcp
- Roblox 공식 Studio Agent Plugin: https://github.com/Roblox/roblox-studio-agent-plugin
- Third-party asset security: https://create.roblox.com/docs/scripting/security/third-party-vulnerabilities

Roblox 공식 MCP 안내에 따르면, 지원 클라이언트를 Studio의 로컬 MCP 서버에 연결하면 열린 Studio의 데이터 모델과 스크립트를 읽고 수정하며, 에셋을 삽입하고 코드를 실행하거나 플레이 테스트할 수 있다. 이 기능은 ChatGPT 웹 대화가 아니라 연결된 ChatGPT 데스크톱 앱/Codex 또는 지원되는 Claude 클라이언트에서 사용해야 한다.

### 다이어그램 방법론 참고
- Architectural diagramming: https://archstudent.com/process/architectural-diagramming/
- Brief, site and programme: https://www.studiomatrx.org/students/architectural-design-1/brief-site-programme
- Programming and space planning: https://www.studiomatrx.org/students/architectural-design-6/programming-and-planning

방법론의 요지: 공간 프로그램을 정리하고, 인접 관계와 버블/존닝을 검토한 뒤 동선과 매스를 비교한다. 다이어그램은 한 장에 모든 판단을 넣기보다 프로그램·동선·매스 등 각기 다른 질문을 분리해 표현한다.

사용자가 제공한 네이버 블로그 URL도 참고 대상으로 받았으나, 자동 열람에서는 본문을 가져오지 못했다. 따라서 위의 방법론 설명을 해당 블로그의 세부 주장에 대한 요약이라고 보지 않는다.

- [ ] 인접 관계와 최소 2개의 대안 배치가 비교되어 있다.
- [ ] 주요 이동 경로와 선택적 동선이 표시되어 있다.
- [ ] 매스 다이어그램과 회색 블록아웃이 서로 대응한다.
- [ ] Creator Store 후보는 검증 상태와 함께 기록되어 있다.
- [ ] Studio에서 실제 이동·카메라·상호작용·성능을 테스트한 결과를 기록한다.
- [ ] 사용자 승인 전까지 배치를 확정안으로 표시하지 않는다.


## 10. 이번 대화에서 추가된 설계 워크플로 결정

사용자 참고 링크:
- 네이버 블로그: https://blog.naver.com/gamemovie97/223717208624
- 링크는 참고 자료로 등록했으나, 자동 열람에서 본문을 가져오지 못했다. 따라서 이 문서가 해당 글의 내용을 직접 요약하거나 검증했다고 주장하지 않는다. 사용자가 본문/캡처를 제공하면 관련 원칙을 별도 비교한다.

### 사용자가 제공할 입력과 설계자가 만들 산출물

사용자는 기존 문서에 기록된 공간 목록을 다시 작성할 필요가 없다. 공간의 목적이나 우선순위가 바뀌면 변경된 부분만 알려준다. 설계 초안은 기존 `WORLD_CONCEPTS_AND_INTERACTIONS.md`와 각 공간 문서를 기준으로 만든다.

설계 산출물 순서:
1. **공간 프로그램 표:** 공간별 행동, 체류 성격, 필수 요소, 요구 면적의 상대적 크기.
2. **인접 관계도:** 필수 연결/가까운 관계/분리할 관계를 구분한다.
3. **버블 다이어그램 2~3안:** 서로 다른 배치 가설을 만든다. 이 단계는 축척이 정확한 평면도가 아니다.
4. **동선도:** Spawn, 주요 경로, 선택 경로, 순환 루프, 목적지, 시야 랜드마크를 표시한다.
5. **매스 다이어그램 2~3안:** 공간 덩어리의 상대적 크기·높이·개방감·랜드마크 위계를 비교한다.
6. **평가표:** 길 찾기, 소셜 만남, 공간별 정체성, 사진 구도, 이동 거리, 모바일 가독성, 제작 비용, 확장 가능성으로 각 안을 비교한다.
7. **권고안과 미확정 사항:** 추천안을 제시하되, 사용자가 선택하기 전에는 확정하지 않는다.
8. **Studio 회색 블록아웃 명세:** 대략적인 구역 크기/위치, 통로, 임시 표지, 확인해야 할 카메라/충돌/이동 테스트를 기록한다.

### 배치안 비교의 원칙

- 한 가지 배치를 정답처럼 바로 제시하지 말고, 중요한 상충관계가 있는 경우 최소 2개의 대안을 비교한다.
- 장식과 실제 플레이 동선을 구분한다. 통과 동선이 휴식/춤/놀이 구역을 가로지르지 않게 한다.
- 포털을 사용해 이동을 단순화할 수 있지만, 허브·랜드마크·공간의 상대적 관계를 설계하지 않은 채 포털만 나열하는 방식은 피한다.
- 공간의 높이와 시야는 탑뷰만으로 판단하지 않는다. 매스/카메라 관점과 Studio 플레이 테스트에서 검증한다.
- 초안은 건축/공간계획 방법론을 적용한 설계 제안이다. 실제 Roblox 플레이테스트 전에는 최적 배치로 단정하지 않는다.

### ChatGPT와 Studio 연결 범위

- **이 브라우저 대화:** GitHub 연결 도구로 저장소의 문서/코드를 읽고 수정·커밋할 수 있다. 하지만 사용자의 로컬 Roblox Studio 세션에 직접 연결되어 있지 않으면 Studio 오브젝트를 직접 배치하거나 플레이 테스트를 실행할 수 없다.
- **ChatGPT 데스크톱 앱 + Roblox Studio MCP/공식 Agent Plugin:** 지원되는 클라이언트를 로컬 Studio MCP에 설정해 연결하면, 해당 연결이 허용하는 범위에서 Studio DataModel/스크립트/에셋/테스트 작업을 수행할 수 있다. 연결 설정과 권한이 필요하며, 이 브라우저 대화가 자동으로 그 연결을 상속하는 것은 아니다.
- **GitHub:** 프로젝트의 소스/문서와 변경 이력을 관리한다. Studio MCP를 대체하지 않으며, MCP도 GitHub의 버전 관리 필요성을 없애지 않는다.
- 공식 안내: https://create.roblox.com/docs/studio/mcp
- 공식 플러그인 저장소: https://github.com/Roblox/roblox-studio-agent-plugin
