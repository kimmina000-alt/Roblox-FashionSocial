## 1. 기반 정리 (기능이 아니라 안전장치)
1. **브랜치 합치기** — 승인 후 `catalog-ui-redesign`(→ main)으로. 큰 작업이 한 브랜치에 쌓여 있어 가장 위험한 미결 항목.
2. **실제 저장(DataStore) 확인** — 게임이 게시됨("오후"). 라이브 비공개 서버(또는 Studio API 접근 허용)로 사진첩·코인·XP·옷장·즐겨찾기가 재접속 후 남는지. (ISSUE-QA-006)
3. **실제 결제 확인** — 상품 ID 넣고 라이브 서버에서 VIP 벽 통과, DJ 시간, 환타, 프레임 팩, 사진첩 칸 구매 1회씩.
4. **회색 박스를 전부 스크립트로** — 05_Cafe·08_PhotoBooth·09_Paths가 아직 "스냅샷"(Studio에서 옮긴 좌표를 베낀 것). 배치 고정 전에 정리.

## 3. 배치 고정 (Layout freeze)
- 전체 맵을 모바일 2인으로 한 바퀴: 이동 시간, 시야, 막힌 길, 표지판. 문제 고친 뒤 **좌표 고정** 선언(DECISIONS에 기록).

- 라이브 테스트 서버에서 다수 인원(가능한 많이) + 저사양 휴대폰: 프레임, 메모리, 네트워크. 지금 맵 약 1,500 파트. (PERFORMANCE.md §4)
- 이 숫자가 "아트 예산"(구역별 파트·텍스처 한도)이 된다.
