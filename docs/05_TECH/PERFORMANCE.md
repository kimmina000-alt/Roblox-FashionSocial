# 성능(렉) 점검 — 2026-10-21

질문(사용자): "사람이 많아지면 렉이 심하지 않을까? 클럽·인생네컷 외에는 상호작용 정도(공원 관람차·회전목마·그네)만 넣을 것."

Roblox 기준으로 1천 개 안팎은 **아주 가벼운 맵**이다(일반 소셜 게임은 수만 개). 지금 렉을 만들 요인은 맵이 아니라 아래 항목들이다.

## 2. 사람이 많을 때 실제로 무거운 것 (큰 순서)
1. **아바타 자체** — 30명이 레이어드 의상·큰 머리카락을 입으면 이게 가장 무겁다. 패션 게임이라 피할 수 없고, Roblox가 거리별로 자동으로 줄인다(아바타 LOD). 우리 쪽 대책: 서버 인원 24~30 유지.
2. **춤 애니메이션** — 사람마다 트랙 1개. 30명이 동시에 춰도 Roblox 기본 이모트 수준이라 문제없다. 같이 추기는 속성 몇 개만 바뀐다.
3. **클럽 연출(클라이언트에서만 그림)** — 레이저 8개×4줄=32줄, LED 기둥 4개×16면. 둘 다 **260 stud 안에 있을 때만** 그리고 초당 30번만 갱신. 클럽 밖에서는 0. 서버 부담 없음.
4. **인생네컷 사진 그리기** — 고르기 화면에서 아바타 복제가 8~12개(사람 수 × 장 수) 생긴다. 고르는 동안·사진첩을 열었을 때만, 한 장씩 차례로 그린다. 휴대폰에서 가장 무거운 순간이지만 짧다.
5. **서버 반복 작업** — 0.25~10초 간격의 작은 검사(부스 결계, 클럽 출입, 코인, DJ). 30명 기준 매우 가볍다.
6. **네트워크** — 춤·DJ·코인은 속성 몇 개라 거의 0. 사진 저장만 수 KB.

→ **결론: 지금 기능과 30명 정원으로 렉이 "심해질" 요인은 없다.** 가장 무거운 건 아바타(게임 성격상 당연)와 휴대폰의 사진 고르기 화면이다.

## 3. 공원 놀이기구를 넣을 때 지킬 것
| 기구 | 권장 방식 | 피할 것 |
|---|---|---|
| 관람차 | 바퀴 전체를 **하나의 모델**로 만들고 HingeConstraint(모터) 1개로 돌림. 칸(곤돌라)은 바퀴에 매달린 좌석 | 매 프레임 스크립트로 수십 개 파트 CFrame 옮기기 |
| 회전목마 | 원판+말을 하나로 묶어 모터 1개 | 말마다 따로 회전 |
| 그네 | 그네마다 HingeConstraint 1개, 앉으면 살짝 밀어 줌 | 물리 체인(로프 여러 마디) |
- 놀이기구가 비어 있으면 멈추고(사람이 탈 때만 회전), 멀리 있으면 StreamingEnabled가 알아서 뺀다.
- 기구당 파트 50~150개면 충분하다(맵 전체가 2천 개를 넘지 않게).

## 4. 앞으로 확인할 것
- 실제 30명 서버에서 MicroProfiler로 프레임 시간 확인(출시 전 테스트 서버).
- 휴대폰(저사양)에서 사진 고르기 화면과 클럽 안 프레임.
- 카페 알바(제안)를 넣으면 NPC 손님 수를 제한(동시에 2~3명).
